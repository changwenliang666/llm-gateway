## Context

选路、轮询和适配器注册已经分开。`RateLimiter` 目前全放行。熔断不存在。模型地址在 `models.base_url`，可调度账号来自 `model_accounts` 与启用的账号、Key 的交集。Google、字节若走 OpenAI 兼容协议，只需新增模型行；若走原生协议，新增一个 `ProtocolAdapter` Bean。准入逻辑不能写进适配器。

## Goals / Non-Goals

**Goals:**

- 熔断、限流、负载均衡开关都按模型生效，对话和视频走同一套准入。
- 多实例下计数和熔断状态用 Redis Lua 原子更新。
- 管理端复用现有表，Key 只出掩码，适配器列表来自注册表。

**Non-Goals:**

- 账号级限流、账号级熔断、权重、健康度、自动故障转移的新层次。
- 登录用户体系、图像适配器、Google 或字节的具体协议实现。

## Decisions

- 负载均衡关闭时固定选快照中第一个账号（SQL 已按账号 id 升序），不 INCR 账号游标。Key 游标照常。已有数据默认开启，避免升级后从轮询变成钉死。
- 开启校验使用和运行时相同的可调度账号集合，而不是供应商名下全部已启用账号。未挂到模型上的账号本来就不会被选中。
- 限流在选账号之前。RPM 与 TPM 同一条 Lua，超限两个都不加。TPM 调用前按出站 JSON 字节数除以 4 估算，至少为 1。非流式响应若适配器报出 `total` Token，再按差额修正。修正失败只记日志，不把已经成功的上游结果改成错误。
- 熔断键 `llm-gateway:cb:{modelId}`。连续失败默认 5 次，冷静期默认 30 秒，半开同时 1 个试探。试探租约默认 120 秒，进程在试探途中退出后，下一次请求可以重新取得名额。OPEN 拒绝发生在限流之前，不消耗配额。
- 502、504 和上游 5xx 记失败。4xx、本网关 429、Redis 轮询失败记放弃或忽略，不开熔断。流式一旦开始写出，记成功，且不重试。
- 保留现有一次 `nextAccount` / `nextKey`。它只发生在还没向调用方写字节时，熔断看这次请求的最终结果。
- 管理写库用独立 Mapper。只读的 `ModelCatalogMapper` 继续不写。`/admin/api/**` 校验 `X-Admin-Token`。页面是静态文件，由同一进程提供。
- Token 用量由适配器自己解析。`OpenAiChatAdapter` 读 `usage.total_tokens`。万相没有用量则不修正。以后的原生协议覆盖同一方法即可。

## Risks / Trade-offs

- [固定一分钟窗口在分钟交界可能放进约两倍流量] → 第一版接受。窗口键带 UTC 分钟，多实例看到同一桶。
- [TPM 估算和真实用量有偏差] → 有用量时事后修正；流式保持估算。
- [半开试探进程崩溃会占住名额] → 试探租约到期后允许新的试探。
- [管理接口能改密钥] → 独立令牌，未配置则全部 401。调用接口不带这个要求。

## Migration Plan

1. 对已有库执行 `sql/model_governance.sql`。不要执行 `sql/schema.sql`。
2. 配置 `ADMIN_TOKEN` 后重启进程。
3. 新列默认负载均衡开启、限流关闭，现有调用路径保持轮询且不限流。
4. 回滚时停用新进程即可。新增列可留在表上，旧进程不读它们。

## Open Questions

无。冷静期、失败次数和试探数用配置默认值，不做到每个模型的管理项。
