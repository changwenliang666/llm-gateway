# 第 0 课：怎么用这套课把项目真正学懂

这套课不是项目说明书的改写版。它按「先知道业务在干什么，再知道代码为什么这样拆，最后能打开 IDE 跟着走一遍」来写。依据是当前仓库里的真实代码，写文档时对照过 `pom.xml`、`application.yml`、`sql/`、`src/main/java` 和测试。

如果你只把文档读完，觉得「好像懂了」，这套课就失败了。正确的用法是：读一小节，立刻在 IDE 里打开它点名的类，用断点或肉眼把那几行对上。

## 你现在的起点

你已经会 JavaScript、TypeScript、Vue 和 Node.js。网关是 Java 21 + Spring Boot 3.5.16 写的。下面这些词后面的课会先解释再使用，这里只给一张对照表，方便你第一次看到时不慌。

| Java 里的东西 | 你可以先把它想成 | 在本项目里出现在哪 |
| --- | --- | --- |
| `@RestController` | 一个专门接 HTTP 的路由处理函数 | `ChatCompletionController`、`VideoController` |
| `@Service` / `@Component` | 被框架创建并保管的对象，不用自己 `new` | `ChatCompletionService`、`RouteResolver` |
| 构造方法注入 | 函数参数里的依赖，由框架传入，类似把 axios 实例传进 composable | 几乎每个类的构造方法 |
| 接口 | 一份约定。调用方只认约定，不认具体牌子 | `ProtocolAdapter`、`RateLimiter` |
| `record` | 一个只有数据、字段不可变的小对象，类似只读的 TypeScript 类型加对象 | `ModelRoute`、`InvokeCommand`、`Permit` |
| MyBatis Mapper | 接口上的方法名对应 XML 里的 SQL，类似一个很薄的数据访问层 | `ModelCatalogMapper` |
| Redis | 一块所有网关进程共用的内存黑板 | 轮询游标、限流计数、熔断状态 |

类比只负责让你进门。后面每一课都会回到 Java 里那几行真正执行的代码。

## 先建立一张真实的知识地图

一次文本对话，代码里的顺序就是下面这张表。视频创建几乎相同。视频查询会锁回创建任务的账号，这是后面要单独记的差别。

| 步骤 | 类与方法 | 这一步在回答什么 |
| --- | --- | --- |
| 接 HTTP | `ChatCompletionController.chat` | 请求来了，自己不读模型名 |
| 读 JSON | `JsonBodies.object` / `requiredText` | 正文是不是对象，有没有 `model` |
| 算超时 | `HeaderTimeoutPolicy.resolve` | 这次最多等多少毫秒 |
| 查模型并组快照 | `RouteResolver.resolve` | 模型是否启用、适配器在不在、有没有账号 |
| 协议是否匹配 | `ProtocolAdapter.supports` | 视频模型不许打对话接口 |
| 改成上游认识的正文 | `ChatCompletionService.rewritePlainMessage` | 把 `message` 收成一条 user 消息 |
| 选账号，并跳过已熔断的账号 | `RoundRobinAccountLoadBalancer.select` | 打哪一个账号、用哪一把 Key。熔断按模型加账号 |
| 模型级限流 | `ModelAdmission.enter` | 这个模型最近 60 秒的 RPM 满了没有 |
| 发 HTTP | `OpenAiChatAdapter.invoke` → `UpstreamClient.send` | 真正访问供应商 |
| 记账 | `CallRecords.record` | 写入 `model_tasks` |
| 必要时换账号再试一次 | `loadBalancer.nextAccount` | 仅 401、429、5xx，且还没把字节写给调用方 |
| 回写熔断和 Token | `ModelAdmission.observe` / `finish` | 换账号时前一个账号先记自己的结果；最后一次成功清零该账号的失败次数，失败累加，4xx 不计失败 |
| 把结果交还调用方 | `ResponseWriter.writeBuffered` 或流式拷贝 | 非流式最后才写；流式边收边写 |

把这张表抄到一张纸上。后面任何一课讲到某个类，先问自己：它在这张表的哪一行。

## 项目实际有的能力

这些是代码里真的做了的，面试和改代码都只能讲这些。

- 文本对话：`POST /v1/chat/completions`。适配器名是 `openai`。通义千问、DeepSeek 共用这一份代码。`stream: true` 时按 SSE 边收边转发。
- 万相视频创建：`POST /v1/video/synthesis`。适配器名是 `dashscope-wan`。创建后立刻返回任务号，不等视频做完。
- 视频查询：`GET /v1/tasks/{taskId}?model=`。有任务记录时回到创建它的账号。
- 模型级滑动窗口限流：最近 60 秒内的 RPM，计数在 Redis，一个模型一份。分钟整点不会把额度清零。网关不执行 TPM。供应商的 TPM 错误按上游正文返回。
- 账号熔断：关闭、打开、半开。Redis 键是模型 id 加账号 id。一个账号打开，同模型的其他账号还能被选中。状态在一段 Lua 里改完。
- 账号轮询和同一账号内的 Key 轮换。负载均衡可以按模型关掉，关掉后钉住 id 最小的账号；这个账号如果已熔断，直接 503，不改投后面的账号。
- 上游返回 401、429 或 5xx，并且响应还没写给调用方时，换下一个还没熔断的账号再试一次。超时和连接失败不换账号。
- 每次文本调用、每次视频创建写入 `model_tasks`。查询只更新状态。
- 管理页：Vue 3 控制台，走 `/admin/api/**`，用 `X-Admin-Token`。它不在模型调用链上。

## 项目没有的能力

下面这些如果在别的网关文章里见过，不要安到本项目头上。文档后面如果提到，会明确写成「扩展知识，当前没做」。

- 没有图像生成接口，没有 `ImageController`。
- 没有按账号限流，也没有按调用方限流。请求头 `X-Gateway-Client-Id` 只是被读进来放着，限流逻辑不用它。熔断已经按账号分开，不要把它说成还没做。
- 没有令牌桶、漏桶。限流是滚动 60 秒的滑动窗口，不是按 UTC 分钟清零的固定窗口。
- 没有 Resilience4j、Sentinel 这种现成熔断库。熔断是自己写的 Redis Lua。
- 没有一个名叫 Factory、里面 `new` 出不同适配器的类。适配器是 Spring 启动时收集的。第 8 课会把这件事和教科书里的工厂模式对齐，避免你面试时说错。
- 超时不会自动再试一次。超时也不等于上游已经停止生成。
- 文本请求没有防重复提交。同一次用户连点两下，会记成两行任务。
- 模型调用这一路没有包在一个数据库事务里。`@Transactional` 只出现在管理端保存配置的 `AdminService` 上。
- 没有 Prometheus、没有调用链追踪。成功时打一行 `log.info`，失败时在对应位置打 warn 或 error。
- 公开接口没有单独的 DTO 类。正文用 Jackson 的 `ObjectNode` 直接改。

## 目录怎么打开

从仓库根目录看，业务代码都在 `src/main/java/com/llmgateway/`。按这个顺序点开包，不要一上来就钻管理页。

| 包 | 你要建立的直觉 |
| --- | --- |
| `web` | 门卫。只把 HTTP 请求交给服务 |
| `gateway` | 调度员。规定先检查什么、再调用谁、失败换不换账号 |
| `routing` | 查配置、选账号、限流、熔断 |
| `upstream` | 把已经选好的账号，翻译成某一家供应商认识的 HTTP |
| `task` | 把调用记进 `model_tasks` |
| `timeout`、`error`、`config` | 超时预算、错误 JSON、MySQL 和 Redis 怎么连上 |
| `admin` | 给人改配置的后台，不参与 `/v1` 调用 |

配置表在 `sql/schema.sql`。已经有库时不要执行这个文件，它会先删表。缺列时用同目录里那几个补丁脚本，README 写了哪个脚本补哪一列。

进程入口是 `LlmGatewayApplication.main`。它做两件和新手有关的事：启动 Spring Boot；只把标了 `@Mapper` 的接口交给 MyBatis。限流、熔断那些接口没有 `@Mapper`，所以不会被误当成 SQL 接口。

## 怎么在 IDE 里跟着学

1. 用 IDE 的「转到定义」从 `ChatCompletionController.chat` 进到 `ChatCompletionService.handle`。
2. 每进入一个方法，先看它的参数和返回值，再看方法上面的注释。这个项目的注释写的是顺序和边界，不是空话，值得读。
3. 看到 `throw new GatewayException(...)`，就到 `GatewayExceptionHandler` 看它最后变成什么样的 JSON。
4. 看到接口类型（例如方法参数是 `ProtocolAdapter`），用「查找实现」看真正运行的是哪个类。文本是 `OpenAiChatAdapter`，视频是 `DashScopeWanAdapter`。
5. 不要从 `console/` 开始读。那个目录是管理页，类似你熟悉的 Vue 前端。模型调用不经过它。

本地跑起来需要 JDK 21、MySQL 和 Redis。连接信息放在环境变量或被 git 忽略的 `application-local.yml`，不要写进会提交的文件。管理页开发时另开一个终端，在 `console/` 里 `npm run dev`，浏览器访问 `http://localhost:5173/admin/`。

## 读的时候抓住六句人话

后面所有细节都是在展开这六句。能背下来并举出类名，项目就入门了。

1. 调用方只访问网关，供应商地址和 API Key 在 MySQL 里，调用方不带上游 Key。
2. 选账号时先看这个账号在这个模型上的熔断。打开的跳过。账号选定之后，再查这个模型的限流。
3. 选账号的人不知道供应商协议，翻译协议的人不知道要不要重试。
4. 文本和视频的差别主要在协议和「查询必须回到创建任务的那个账号」。那个账号自己熔断了，查询也不改投。
5. 限流看的是这个模型最近 60 秒用了多少。熔断看的是这个账号是不是在连续失败。一个账号打开，不影响同模型的其他账号，也不影响别的模型。
6. 超时是网关不再等了，不是上游一定停了。超时不换账号，401、429、5xx 才有一次换账号的机会。

## 本课练习

### 入门

不看文档，说出三个对外路径，以及它们分别只接受哪种适配器。

参考答案：`POST /v1/chat/completions` 只接受声明了 `CHAT_COMPLETION` 的适配器，当前是 `openai`。`POST /v1/video/synthesis` 只接受 `VIDEO_CREATE`，当前是 `dashscope-wan`。`GET /v1/tasks/{taskId}?model=` 只接受 `VIDEO_QUERY`，同样是 `dashscope-wan`。文本模型打到视频接口会得到 400，文案是「该模型不能用于视频接口」或「该模型不能用于视频查询」。

### 进阶

为什么管理页的 Vue 代码不是模型调用链路的一部分？

参考答案：业务系统调用的是 `/v1/**`，进入 `web` 包的控制器，再进 `gateway` 编排。管理页请求的是 `/admin/api/**`，先过 `AdminAuthFilter`，再进 `AdminController`。它改的是 MySQL 里的配置。下一次 `/v1` 请求会重新查库，所以配置能生效，但这一次模型调用本身不经过 Vue，也不经过 `AdminService`。

### 实战

在 IDE 里只做这一件事：从 `ChatCompletionController` 跳到 `ChatCompletionService.handle`，把方法里的本地变量名抄下来（`body`、`model`、`timeout`、`route`、`adapter`、`stream`、`estimate`、`permit`、`selected`、`result`）。下一课开始，每认识一个类，就回来标它改的是哪个变量。
