# 第 10 课：动手练习与参考答案

前面每一课末尾已经有随堂题。这一课换成「你真的要改项目或排障」时会遇到的题。每题都给出要打开的文件。先自己写步骤，再对答案。

## 入门

### 1. 新增一个已有协议的模型配置，要动哪些地方？

场景：再接入一个 OpenAI 兼容的模型，名字叫 `vendor-x-small`。不要写新的 Java 类。

参考答案：

1. 确认进程里已经有 `OpenAiChatAdapter`，`name()` 是 `openai`。不用新类。
2. 在管理页或数据库新增供应商和账号、Key。Key 只在创建时提交明文。
3. 新增 `models` 行：`model_name` 为 `vendor-x-small`，`adapter_name` 为 `openai`，`base_url` 为对方文档里的完整地址，`upstream_model_name` 为对方真实模型名，`enabled` 为 1。
4. 在 `model_accounts` 挂上属于这个供应商的账号，链接启用。
5. 若打开负载均衡，可调度账号至少两个，否则管理接口 400，开关不会被改成开。
6. 不用重启即可被下一次 `RouteResolver.resolve` 读到。前提是适配器类本来就在运行的进程里。

会用到这些代码，但不用改：`ModelCatalogMapper.selectByName`、`selectCandidates`、`OpenAiChatAdapter.invoke`。

不要做的事：不要在 `ChatCompletionService` 里加 `if (model.equals("vendor-x-small"))`。不要把 Key 写进 `application.yml`。

### 2. 怎样确认某个类是请求链路的一部分，而不是管理页的？

参考答案：看谁调用它。`AdminController` 和 `AdminService` 只服务 `/admin/api`。模型调用从 `ChatCompletionController` 或 `VideoController` 进来。`AdminAuthFilter.shouldNotFilter` 对不是 `/admin/api/` 的路径直接放行，所以调用方不需要管理令牌。

## 进阶

### 3. 一次对话返回了 400，怎样判断是网关挡的，还是上游挡的？

参考答案：

看响应正文。若是 `{"error":{"message":"...","type":"invalid_request_error"}}`，这是 `GatewayExceptionHandler` 写的。再到消息对表：

| message | 位置 |
| --- | --- |
| 请求体不是合法 JSON / 请求体必须是 JSON 对象 | `JsonBodies.object` |
| 缺少模型名 | `JsonBodies.requiredText` |
| 超时必须是正整数毫秒 | `HeaderTimeoutPolicy.resolve` |
| 不支持的协议适配器 | `RouteResolver.resolve` |
| 该模型不能用于对话接口 | `ChatCompletionService.handle` |
| message 必须是非空字符串 | `rewritePlainMessage` |

若正文不是这套 `error` 结构，而是上游自己的 JSON，状态码仍是 400，说明请求已经 `UpstreamClient.send` 出去了。`retryableStatus` 不包含 400，所以没有换账号。熔断按 `NEUTRAL`，不记失败。

同时看日志里有没有「调用完成」。网关自己在选账号前抛出的 400，不会打那行「调用完成」，因为它在 `handle` 后半段。

### 4. 某个模型频繁 504，调用方还在重试。你先看什么，先不改什么？

参考答案：

先确认是不是同一个模型、同一个账号。熔断键是 `llm-gateway:cb:{modelId}:{accountId}`。连续 5 次超时打在同一个账号上会打开这把键。之后选路会跳过它。别的账号都打开时，30 秒内才应看到 503「模型暂时不可用」，而不是继续 504。如果一直 504，说明失败被轮询拆到了不同账号、没有累计到阈值，或者你看的不是这套 Redis。

超时不会换账号，所以不要先去调轮询。也不要先把超时改成 5 秒，那会让正常长回答全部失败。

先看 `UpstreamClient` 的 warn「上游超时」以及「调用完成」是否根本没打印。504 发生在 `send` 抛异常的路径，`handle` 的成功日志不会出现。任务表里应有 `recordFailure` 写下的 `FAILED` 行，那是对话和创建的行为。

调用方立刻重试会在熔断打开前继续给上游加压。这是调用方的策略，网关不会把 504 自动再打一次。

### 5. 视频查询返回 503「创建任务的账号已不可用」。数据上是什么意思？

参考答案：`model_tasks` 里有这个 `task_id`，`findAccountId` 返回了账号 id。`RoundRobinAccountLoadBalancer.selectKey` 在本次 `ModelRoute.accounts` 里找不到它。常见原因是账号被停用、链接被停用、Key 全部停用，或账号被改到了别的供应商，导致 `selectCandidates` 把它过滤掉。代码故意不改投其他账号。要把原账号重新变成可调度，或接受这个任务不能查。不要为了让 503 消失去改查询逻辑去轮询别的账号，那样会拿别人的 Key 查一个不属于它的任务。

## 实战

### 6. 把「没传超时头时的等待」改成 45 秒

参考答案：

优先设环境变量 `GATEWAY_DEFAULT_TIMEOUT_MS=45000`。它对应 `application.yml` 里的 `gateway.default-timeout-ms`，绑到 `GatewayProperties.defaultTimeoutMs`，由 `HeaderTimeoutPolicy` 在头为空时使用。

不要改 `OpenAiChatAdapter`。视频创建和查询走同一个 `TimeoutPolicy`。

连接超时仍是 `GATEWAY_CONNECT_TIMEOUT_MS`，默认 10 秒。45 秒的业务预算不会自动改变握手时间。

单次调用也可以只加请求头 `X-Gateway-Timeout-Ms: 45000`，不改全局。

改完后用一个不存在的端口或一个会拖延的上游做验证。本仓库测试里有 `PausingHttpServer` 和 `GatewayHttpTest` 可以参考作者怎样断言超时，但你若没有把握，不要为了练习去改测试的断言阈值。

### 7. 给文本请求增加一个「原样转发」的字段，要改代码吗？

场景：调用方想多传 `temperature: 0.2`。

参考答案：不用改。`rewritePlainMessage` 只动 `message` 和 `messages`。`disableThinkingByDefault` 只在缺少 `thinking` 时补字段。`temperature` 留在 `ObjectNode` 里，`replaceModel` 序列化时一起发出去。

必须改代码的字段只有那些网关会解释的：`model` 会被上游名覆盖；`message` 会被收成 `messages`；`stream` 决定是不是 SSE；`thinking` 有默认值。

如果你要的是网关自己的新行为，例如「没有 temperature 时默认 0」，那才要在 `ChatCompletionService` 里加一段和 `disableThinkingByDefault` 同类的改写，并且要避免误伤视频。不要把这种改写放进 `JsonBodies`，那个类的注释写了它只做与协议无关的三件事，视频也会用它读 JSON。

### 8. 新增一家原生协议厂商，最小改动清单

参考答案：

1. 新建类实现 `ProtocolAdapter`，加 `@Component`。`name()` 与将来的 `adapter_name` 完全一致。`label()` 是管理页上的名字。
2. `supports` 里声明你真的实现了的操作。只做文本就只返回 `CHAT_COMPLETION`。
3. `invoke` 里从 `command.selection()` 拿 URL 和 Key，用 `UpstreamClient.send` 发出去。可重试状态继续用 `JsonBodies.retryableStatus`，这样编排层的换账号规则不用复制。
4. 返回 `InvokeResult.buffered` 或在你真的写了响应之后返回 `streamed`。不要在适配器里调用 `nextAccount`。
5. 有总 Token 字段就实现 `reportedTotalTokens`。
6. 重启进程。`AdapterRegistry` 会把新 Bean 收进 Map。管理页适配器列表来自 `all()`，不用改 Vue 的写死数组。
7. 插模型行和账号。用对应的入口打一次。文本入口会拒绝不支持对话的适配器。

不用改的：`ModelAdmission`、`RoundRobinAccountLoadBalancer`、`ChatCompletionController` 的路径、限流 Lua。

### 9. 模型频繁报错时，怎样让调用先停下来？

参考答案：

当前没有管理接口去手动打开熔断。自动路径是某一个账号上的连续超时、连接失败或 5xx 达到 `GATEWAY_CIRCUIT_FAILURES`，默认 5。负载均衡开着时，只跳过这个账号。这个模型上的账号都打开之后，`GATEWAY_CIRCUIT_OPEN_MS` 毫秒内才返回 503。

如果你要立刻停掉，正确的现成手段是把模型 `enabled` 设为 0。下一次 `resolve` 返回 404，「模型不存在或已停用」，不会打上游，也不会靠熔断计数。这和熔断的差别要讲清楚：停用是配置，404；熔断是运行时连续失败，503，过一会儿还会试探。

不要用「把 RPM 改成 1」假装熔断。那是另一套语义，健康请求也会被 429，而且 429 不计失败。

### 10. 定位一次失败时，建议的查看顺序

参考答案：

1. 看 HTTP 状态和正文是不是网关的 `error` 结构。是的话用第 3 题的表对位置。
2. 不是的话，请求已经到过上游。看状态是 4xx 还是 5xx。4xx 不记熔断。5xx 记。
3. 没有任何上游正文、状态是 504 或 502，看 `UpstreamClient` 的日志和 `model_tasks` 里是否多了 `FAILED`。
4. 状态是 503 且文案是「模型暂时不可用」，看 Redis 键 `llm-gateway:cb:{modelId}:{accountId}` 的 `state` 和 `openedAt`。账号 id 从「调用完成」日志或上一轮任务行里取。负载均衡开着时，要确认是不是每个候选账号都开着，而不是只看了其中一个。
5. 文案是「没有可用的供应商账号」或「创建任务的账号已不可用」，查五张配置表的 `enabled`，不要先怀疑熔断。
6. 文案是「轮询计数不可用」「限流计数不可用」「熔断状态不可用」「任务绑定不可用」，这是 Redis 或 MySQL 的基础设施失败，不是模型内容错误。

## 综合题

### 11. 不看文档，按顺序说出文本主路径上的 8 个类

参考答案：`ChatCompletionController`、`ChatCompletionService`、`RouteResolver`、`ModelAdmission`、`RoundRobinAccountLoadBalancer`、`OpenAiChatAdapter`、`UpstreamClient`、`ResponseWriter`。记账类 `CallRecords` 夹在适配器返回之后、`ResponseWriter` 之前。说成 8 个或把 `CallRecords` 算进去都可以，只要顺序不错：准入和选账号在适配器之前，写出在最后。

### 12. 下面做法哪一个会重复扣费或重复生成？哪一个是本项目已经防住的？

甲：超时后网关自动换账号再 POST 一次。

乙：401 后换账号再 POST 一次。

丙：流式已经 flush 了第一段，又换账号重做。

参考答案：

甲不是当前代码。若加上，两家上游可能都在生成。当前超时不重试，防的就是这个。

乙是当前代码，只发生在还有另一个账号、且字节没写出时。第一次若是 401，通常还没开始生成内容，换 Key 是合理的。若第一次其实是 500，上游可能已经收下了请求，第二次仍可能双份。项目接受「最多再试一次」，没有取消第一次。

丙被 `committed` 防住。流式 2xx 不会再 `nextAccount`。

## 自测方式

选一道实战题，在纸上写出文件路径和方法名，再打开 IDE 核对。对不上就回到第 9 课的追踪，不要重新通读全部文档。能独立完成第 6、第 8、第 10 题，就说明你已经能改配置、加协议、排故障，而不是只会复述名词。
